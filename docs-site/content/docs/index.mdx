**本页回答**：这个插件做什么、对外有哪些接口、依赖谁、不做什么；它和外面的十二条接缝各传什么、由谁负责、怎么测。

「单元」是一个纯目录约定：容器根（设置 `units-root`，如 `D:\unitfolders`）下一层一个目录，目录里一张 `unit.json` 出生证，
写着种类、短名、一句话自述、状态、图标、出生时刻六项。没有服务、没有索引、没有注册表，整件事只靠读写磁盘就能做完。
`@godcreator/gwb-unit-folder` 在这个约定上做四件事：

- **现扫**：每次调用都重新列一遍容器根、读每个单元的出生证，按种类分组；不缓存，刚建的单元立刻看得见
- **建单元**：算目录名（五位随机小写字母数字，可带功能名，如 `igldu-gwbkernel`）、建目录、写出生证，到 `unit.json` 为止
- **浏览**：单元树里展开单元看文件，点文件在原文窗格里看原文；也能在资源管理器或 VSCode 里打开目录
- **报选中与置顶**：人在树上点了哪个单元、置顶了哪几个单元，经服务 `ctx.gwbUnitFolder` 与事件 `unit-folder/selection` 往外报

对外的接口是十一条命令、一个服务、一个事件、两个窗格、一项设置、一份 data 文档和一份说明书，逐项的形状在
[服务与命令](/docs/service-and-commands)，每个依赖的 peer 写法在[插件之间怎么连](/docs/wiring)。

## 接缝图

插件分三个模块：浏览器侧（两个窗格）、node 侧（cordis 服务，负责登记命令与窗格、记住会话状态）、判断与读盘（不依赖 cordis 的函数与磁盘读写）。
模块之外是人、agent、工作台的几个插件、内核、磁盘和两个外部程序。

## 接缝逐条

### 1 浏览器侧 → 命令总线 → node 侧

两个窗格不 import node 侧的任何符号，只经 `host.call('unit-folder.<名>', args)` 通信，回执统一是 `{ ok, data?, error?, code? }`。
node 侧负责校验参数与回执形状；浏览器侧按形状收，缺配置这种要区别对待的失败只认 `code: 'unconfigured'`，不认错误文字。
报选中是其中特别的一次调用：展开单元不等它的回执，失败只在控制台 warn——「当前单元」是给别的插件看的，报告失败不该让单元树卡住：

测试：浏览器侧没有自动测试，产物测试只确认十一条命令名都在 `dist/index.js` 里；界面效果用 `devkit.dev` 装进隔离 home 后看。

### 2 agent → 命令总线 → node 侧

agent 经 MCP 入口 `run {"command":"unit-folder.list"}` 调的是同一组命令、拿同一套回执。命令总线对外开放，所以 node 侧不假定参数来自界面：
带路径的七条命令都先过第 3 条里的路径检查。agent 怎么用这些命令写在随包说明书 `unit-folder` 里。

### 3 node 侧 → 判断与读盘

判断全在右边的模块里，node 侧只负责解出容器根、记会话状态（最近一次点击、置顶表）、广播变化。右边的函数进出都是普通值，测试直接调：
`tests/scan|browse|current|create|vscode|toolbar.test.ts`。

带路径参数的命令共用同一道检查：先现读设置 `units-root`，没配就回 `unconfigured`；再把参数验成容器根**里面**的绝对路径，根自己不算，越出根的一律回「路径不在容器根内」：

{/* ref file="../plugins/unit-folder/src/index.ts" lines="247-257" hash="3d4afaaca5e1" blob="152a9c544697" */}

验证分两道。词法那道看字符串：相对路径按容器根解（不按宿主的工作目录解，那个目录由应用怎么启动决定），`..`、根外绝对路径、换盘符在
`path.relative` 的结果上都看得出来。物理那道看实际位置：NTFS 的 junction / symlink 不改字符串、只改实际指向，根内一条链接能把 `stat` / `open`
带到根外去，所以两端都存在时各自 `realpath` 再比一次；任一端不存在就不拦，「不存在」的错由后面列目录、读文件报。校验之后毫秒级把目录换成链接的竞态不防：
纯 Node 拿不到句柄级的最终路径，本机桌面的使用场景下不值得为它动系统接口：

「当前单元」怎么回落也在右边：本会话点过就是最近那一次，没点过回落到第一个置顶单元，都没有就是 undefined。置顶只在没点过时起作用：

### 4 判断与读盘 ⇢ 容器根

这是唯一一条碰单元目录的接缝。扫描只列容器根下的子目录，散落的文件不是单元，列出来只会让人以为漏了什么；直接子目录里叫 `out` 的也跳过，
那是临时产物区的约定名。**根不存在与扫不动是两回事**：前者（ENOENT）是正常状态——配置可以先于目录写下，换机器、待挂载的盘都会这样——回空表加
`rootExists: false`；根指到文件、没权限、盘掉了才报错，拿空表冒充「这里没有单元」会把人往错的方向引。

不缓存是有意的：一次现扫只是列一个目录、每个子目录读一个小文件，规模几十个；缓存却要回答「谁负责失效、手建的目录什么时候进表」，代价更大。

### 5 node 侧 → 外壳：登记窗格

node 侧在 `[Service.init]` 里调两次 `registerPane`：`main`（单元树，工具窗格，整页一份）与 `viewer`（原文，文档窗格，一份装一个文件），
两者的 `client` / `style` 都是从 `dist/index.js` 算出的 `file://` 地址，再用 `describeSelf` 报显示名「单元文件夹」。注销由外壳登记在本插件的 effect 上，
本插件卸载时窗格自动消失。窗格 id 是契约：保存的布局里存着它们。测试：没有自动测试，装进隔离 home 后用 `shell.panes` 看。

开在哪、同一个文件是否已经开着、预览窗格替不替换全归外壳。单元树是工具窗格，所以单击是预览，Ctrl / ⌘ 单击或中键是正式开一个新标签，再加 Alt 开到旁边：

### 7 node 侧 ⇄ 设置插件

`units-root` 是这个插件唯一的设置项，经 `gwbSettings.define` 声明、存在 `<home>/settings.json`；`cordis.yml` 条目上没有 `config`，也不读环境变量。
每条命令现读一次，不在加载时读成常量；没配时不给默认值，因为容器根是这台机器的事实，编一个只会造成「配置了但不在」的假象。设置插件是局部注入，
不在时本插件照常加载，命令一律回 `unconfigured`。测试：`tests/settings.test.ts` 覆盖设置值到绝对路径的换算（非字符串、空白、相对路径）。

docfirst 插件 `@godcreator/gwb-docfirst-workflow` 建站（`docfirst.create` / `docfirst.create-plain`）时局部注入本插件的服务，经 `unitsRoot()`
读这一项，在容器根里查哪些端口已被别的站占用（见接缝 9）。

### 8 node 侧 ⇄ 数据插件 ⇢ 置顶文档

置顶是人在树上点图钉、插件因这个动作自己写下的，所以是数据不是设置——判据跟外壳把布局存进 data 一样：人在设置界面里手填的是设置，插件因人的操作写下的是数据。
它存在数据插件的文档 `pinned`（`<home>/data/unit-folder/pinned.json`，`{ paths }`）。数据插件加载时把磁盘上那份读进内存；人先点了置顶、数据插件后加载的那种顺序，
以内存里最近的动作为准、反过来写盘：

### 9 node 侧 → 消费方插件

依赖方向是消费方认识本插件，本插件不认识任何消费方：用它的插件局部注入 `gwbUnitFolder`，用 `current()` 取初值、`on('unit-folder/selection')` 听变化，
两样的形状是同一个 `UnitSelection`；要容器根的调 `unitsRoot()`。工具条登记接口 `registerToolbarButton` 按调用方的 fiber 认出登记方的条目与包名，不由登记方自己报；
注销登记在调用方的 effect 上，登记方卸载时按钮自动消失：

{/* ref file="../plugins/unit-folder/src/index.ts" lines="207-237" hash="10c602fa332a" blob="152a9c544697" */}

**此刻注入这个服务的只有 docfirst 插件（只调 `unitsRoot()`），工具条没有登记方**。服务、事件与登记接口仍然是契约，
删掉它们是破坏性版本，要不要删等人决定，见轨迹卡[「工具条登记口没有登记方了」](/trajectory/2026-09-26-toolbar-no-registrant)。

### 10 node 侧 → 内核事件 → 浏览器侧

登记表一变（登记、注销、被替换），node 侧 `gwbKernel.emit({ t: 'gwb-unit-folder-toolbar' })`；浏览器侧用 `window.gwb.on` 听，认出这条后重取
`unit-folder.toolbarButtons`。事件只是提醒，按钮表本身仍经第 1 条取。内核接口用 `requireKernel(ctx)` 从根上下文取，不写进 `inject`。
测试：`tests/toolbar.test.ts` 覆盖事件的认法。

### 11 node 侧 → 外部进程

`unit-folder.open` 启动 `explorer.exe <目录>`，`unit-folder.code` 启动 `Code.exe -n <目录>`。两条都以「进程能不能启动」算成败，不看退出码（explorer 成功时退出码也可能是 1）。

VSCode 必须找到 `Code.exe` 本身：PATH 上的 `code` 是 `.cmd`，Node 修 CVE-2024-27980 之后不开 shell 启动 `.cmd` 会抛 EINVAL；开了 shell，目录名就成了命令文本的一部分，
引号、百分号这些合法的文件名字符会被命令解释器解释。所以用 `where.exe` 找到 `code.cmd`，推出旁边的 `Code.exe`，用独立参数、不开 shell 启动。找不到就回失败，
不改用 shell 拼接——那条路正是要防的漏洞。路径在一次加载期内缓存，中途装了 VSCode 要重新加载本插件才认：

{/* ref file="../plugins/unit-folder/src/vscode.ts" lines="1-28" hash="91fd6b6c0f0d" blob="96ce7943f768" */}

测试：`tests/vscode.test.ts` 覆盖从 `code.cmd` 推出 `Code.exe` 的位置；真正启动进程没有自动测试。

### 12 node 侧 → 说明书插件

局部注入 `gwbSkills`，登记包根的 `skills/` 目录（相对产物写作 `'../skills/'`，所以 `skills` 必须在 `package.json` 的 `files` 里）。
说明书 `unit-folder` 告诉 agent 什么时候用这些命令、怎么用它们回答「X 在哪」「我现在看的是哪个」。缺了说明书插件，agent 读不到这份说明书，命令照常可用。

## 各模块对外能做什么

**浏览器侧**（`src/client/`）：单元树窗格按种类分组列出单元，每行是出生证里的图标、短名与两行自述；可按状态与种类筛选（默认藏起退役的）、按文字筛选；
置顶块不受筛选影响；单元展开出文件树，点文件开原文窗格；工具条上能用 VSCode 打开选中单元或它的一级子目录、复制路径、在资源管理器打开容器根。
原文窗格显示行号、能切换折行、点路径复制绝对路径；二进制文件不显示，超过 512 KB 截断。过滤、展开、目录清单都只存在窗格内存里，关掉再开回到默认。

**node 侧**（`src/index.ts`）：登记十一条命令与两个窗格，提供服务 `gwbUnitFolder`，记住本会话最近一次点击与置顶表，`current()` 变了就广播；
`unit-folder.list` 每次现扫时顺带清掉过期状态——置顶了但目录已不在的从置顶表删掉并存盘，最近一次点击的单元不在了就清掉那次点击，两样清完只广播一次。

**判断与读盘**（`src/scan.ts`、`browse.ts`、`current.ts`、`create.ts`、`vscode.ts`、`toolbar.ts`）：出生证字段表与校验、现扫与分组、路径验证、
列一层目录、读原文、置顶表的形状与增删、`current()` 的回落、建单元、找 VSCode、工具条登记表。不依赖 cordis，都在 `tests/` 里直接测。

## 不做的事

- **不认识任何消费方**：谁要知道当前单元谁来注入本插件，本插件不为某个具体消费方发明契约（轨迹卡[「选中往外报」](/trajectory/2026-09-09-report-selection-not-extension-point)）
- **不认领已有目录、不改已有出生证**：给已有目录补写或改写 `unit.json` 是人的事，或别的插件的事（[刻意不做](/future/not-doing)）
- **不建仓、不建文档站**：建单元到 `unit.json` 为止，插件仓用 `devkit.scaffold`，文档站用 `docfirst.create`（接 docfirst 分区）或 `docfirst.create-plain`（普通 fumadocs 站）
- **不缓存清单、不跨会话记「当前」**：清单每次现扫；`current()` 只存在内存里，重启后是第一个置顶或空
- **不给容器根默认值、不替人建容器根**
- **找不到 `Code.exe` 不改用 shell 启动 VSCode**
- **不防校验之后的链接替换竞态**
