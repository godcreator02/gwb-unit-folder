# 服务面与命令面

这一页是契约。**这里钉着的每一样都有别人对着写代码**：服务面被别的件 inject，命令面被浏览器半与 agent 调，
出生证被人与 agent 手写、被站件读。改任何一样之前先问人——判据见轨迹卡「选中往外报」的「代价与遗留」。

`current()` 的回值形状与事件载荷是同一个 `UnitSelection`。三个字段：`unitPath` 是容器根下那一层的单元目录、
`unitName` 是目录名、`path` 是人点的那个目录（点单元行时等于 `unitPath`，点单元内目录时是那个目录）——
都是绝对路径：

{/* ref file="../src/current.ts" lines="14-22" */}

**为什么读的那半是两个方法而不是一个。** `current()` 会回落到第一个置顶，所以光看它分不出「人点了」还是「没点过、只是置顶了」；
文档站件不用分，但将来要「只在人真点了时才动」的消费方得分——`pinned()` 单独给出来（全部置顶，按置顶先后），两者一比就知道。

**写的那半是登记口**（0.4 起）：`registerToolbarButton(spec)` 把一颗动作按钮放进单元树格的工具条，排在
自家那几颗后面。形状纯声明式、皮不认识登记方——点击与「亮不亮」都按登记里给的命令名走总线，

## 事件 `unit-folder/selection`

`current()` 变了就在提供方的 ctx 上 emit 一次，载荷就是新的 `current()`。**点击与置顶两条路都经同一处判「变没变」**，
所以没点过时置顶 / 取消置顶也会广播——消费方看到的「当前」确实变了：

类型面：消费方只要 `import type {} from '@godcreator/gwb-unit-folder'`，Context 上的 `gwbUnitFolder` 与
Events 上的 `'unit-folder/selection'` 就都有了。两条声明合在文件末尾：

{/* ref file="../src/index.ts" lines="495-502" */}

**它不做的事**：不跨会话（`current()` 只住内存，重启之后是第一个置顶或空）；不给「清空」的口（眼下没有清空的动作，
undefined 只在从有到无时才会出现，比如摘掉了最后一个置顶）。

## 依赖谁

两件是**硬注入**（`static inject`）——缺哪件这个件根本挂不上，名字写死在类的静态属性上；
三件是**局部注入**（`ctx.inject([...])`）——缺哪件本件照挂、只少那一面，接不接得上到挂载时才定：

{/* ref file="../src/index.ts" lines="112-114" */}

- **`gwbShell`**（硬注入）：窗格与自我介绍都经它——没它两格没处挂
- **`gwbCommands`**（硬注入）：十一条命令登记在它身上——没它浏览器半调不到任何东西
- **`gwbSettings`**（局部注入）：唯一一项设置 `units-root` 由它声明；没装它读不到根，命令一律回 `unconfigured`
- **`gwbData`**（局部注入）：置顶落它的文档 `pinned`；没装它置顶只活在内存
- **`gwbSkills`**（局部注入）：本件那份说明书（包根 `skills/`）；没装它只是少这一格

三处局部注入，各自顺带接了那一面的事——声明设置项、把盘上那份读进内存、说明书目录随件回收：

**关系是单向的**：别的件（第一个消费方是文档站件）局部注入 `ctx.gwbUnitFolder` 问「人现在看的是哪个单元」，
它不认识任何消费方——方向是特殊认识一般，判据见轨迹卡[「选中往外报」](/trajectory/2026-09-09-report-selection-not-extension-point)。
