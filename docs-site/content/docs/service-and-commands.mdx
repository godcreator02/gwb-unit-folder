# 服务面与命令面

这一页是契约。**这里钉着的每一样都有别人对着写代码**：服务面被别的件 inject，命令面被浏览器半与 agent 调。
改任何一样之前先问人——判据见轨迹卡「选中往外报」的「代价与遗留」。

`current()` 的回值形状与事件载荷是同一个 `UnitSelection`。三个字段：`unitPath` 是容器根下那一层的单元目录、
`unitName` 是目录名、`path` 是人点的那个目录（点单元行时等于 `unitPath`，点单元内目录时是那个目录）——
都是绝对路径：

{/* ref file="../src/current.ts" lines="14-22" */}

**为什么是两个方法而不是一个。** `current()` 会回落到置顶，所以光看它分不出「人点了」还是「没点过、只是置顶了」；
文档站件不用分，但将来要「只在人真点了时才动」的消费方得分——`pinned()` 单独给出来，两者一比就知道。

## 事件 `unit-folder/selection`

`current()` 变了就在提供方的 ctx 上 emit 一次，载荷就是新的 `current()`。**点击与置顶两条路都经同一处判「变没变」**，
所以没点过时置顶 / 取消置顶也会广播——消费方看到的「当前」确实变了：

类型面：消费方只要 `import type {} from '@godcreator02/gwb-unit-folder'`，Context 上的 `gwbUnitFolder` 与
Events 上的 `'unit-folder/selection'` 就都有了。两条声明合在文件末尾：

{/* ref file="../src/index.ts" lines="396-403" */}

**它不做的事**：不跨会话（`current()` 只住内存，重启之后是置顶或空）；不给「清空」的口（眼下没有清空的动作，
undefined 只在从有到无时才会出现，而现在没有从有到无的路）。
