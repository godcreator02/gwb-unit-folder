# 服务与命令

**本页回答**：本插件对外的契约有哪些——出生证字段表、服务 `ctx.gwbUnitFolder`、事件 `unit-folder/selection`、十一条命令、置顶文档——各长什么样。

这一页是契约。**这里钉着的每一样都有别人对着写代码**：服务被别的插件 inject，命令被浏览器侧与 agent 调，
出生证被人与 agent 手写、被文档站插件读。改任何一样之前先问人——判据见轨迹卡「选中往外报」的「代价与遗留」。

## 服务 `ctx.gwbUnitFolder`

消费方写 `ctx.inject(['gwbUnitFolder'], …)`（或 `export const inject`）拿到这个服务。读的两个方法都同步，写的一个（登记按钮）回注销函数：

{/* ref file="../plugins/unit-folder/src/index.ts" lines="48-60" hash="c7f07a0929cb" blob="55206a0602ef" */}

`current()` 的回值形状与事件载荷是同一个 `UnitSelection`。三个字段：`unitPath` 是容器根下那一层的单元目录、
`unitName` 是目录名、`path` 是人点的那个目录（点单元行时等于 `unitPath`，点单元内目录时是那个目录）——
都是绝对路径：

{/* ref file="../plugins/unit-folder/src/current.ts" lines="5-12" hash="024869063edb" blob="31efe67af1c4" */}

**为什么读的是两个方法而不是一个。** `current()` 会回落到第一个置顶，所以光看它分不出「人点了」还是「没点过、只是置顶了」；
要「只在人真点了时才动」的消费方得分——`pinned()` 单独给出来（全部置顶，按置顶先后），两者一比就知道。

**写的是登记接口**（0.4 起）：`registerToolbarButton(spec)` 把一个动作按钮放进单元树窗格的工具条，排在
本插件自己那几个按钮后面。形状纯声明式、浏览器侧不认识登记方——点击与「可不可用」都按登记里给的命令名经命令总线调，
按钮表经 `unit-folder.toolbarButtons` 交给浏览器侧。这个接口推翻了「选中往外报」否掉的候选 A，判据的前提具备了，
经过见轨迹卡「工具条按钮登记口」：

{/* ref file="../plugins/unit-folder/src/toolbar.ts" lines="1-34" hash="772572daf48d" blob="0b8e41823305" */}

（`pane.instance`）。登记方要开窗格就把它原样传给 `shell.openPane`，新窗格开在单元树旁边、不盖住它

## 事件 `unit-folder/selection`

`current()` 变了就在提供方的 ctx 上 emit 一次，载荷就是新的 `current()`。**点击、置顶、清掉已删单元几条路都经同一处判「变没变」**，
所以没点过时置顶 / 取消置顶也会广播——消费方看到的「当前」确实变了：

{/* ref file="../plugins/unit-folder/src/index.ts" lines="215-220" hash="356673fc2f89" blob="55206a0602ef" */}

类型：消费方只要 `import type {} from '@godcreator/gwb-unit-folder'`，Context 上的 `gwbUnitFolder` 与
Events 上的 `'unit-folder/selection'` 就都有了。两条声明写在文件末尾：

{/* ref file="../plugins/unit-folder/src/index.ts" lines="496-503" hash="bb45bdf6edcd" blob="55206a0602ef" */}

**它不做的事**：不跨会话（`current()` 只存在内存里，重启之后是第一个置顶或空）；没有「清空」命令——
undefined 只在从有到无时才会出现，比如摘掉了最后一个置顶、或者最近一次点击的单元已被删掉而且没有置顶。

## 命令

十一条，全登记在本插件名下；命令总线从调用方取包名，本插件卸载时自动注销。带路径参数的七条共用[同一道路径检查](/docs#两条判据)。
`toolbarButtons` 不带路径、也不碰盘——回的就是服务里那张按钮表。

**建单元**（0.7 起）：`create` 不带路径参数，解出容器根之后把 `kind / title / purpose / icon / status? / slug?` 交给
`src/create.ts` 算目录名、建目录、写出生证；字段不成立一个目录都不建：

{/* ref file="../plugins/unit-folder/src/index.ts" lines="286-308" hash="7421788ea032" blob="55206a0602ef" */}

**选中与置顶四条**是服务的命令入口。`select` 是浏览器侧点树时调的那条，agent 想替人「切到某个单元」
也调它；它先确认目录还在（不在直接回失败），再算出所属单元、记下、变了就广播：

{/* ref file="../plugins/unit-folder/src/index.ts" lines="389-407" hash="4a8be9c96eb8" blob="55206a0602ef" */}

`current` 无参数，回 `{ ok: true, data: current() ?? null }`——回执形状跟本插件其余命令一致，没有「当前」时 data 是 null
而不是缺字段：

{/* ref file="../plugins/unit-folder/src/index.ts" lines="456-463" hash="68d1da297bad" blob="55206a0602ef" */}

`pin` 只认容器根下一层的单元目录，追加到置顶表末尾（已经在的不挪位置），存进 data 文档 `pinned`（`{ paths }`），
**不改最近一次点击**；`unpin` 要给 `path`，摘掉那一个。两条的回执都等存盘完成——写没写成进回执，不悄悄失败：

{/* ref file="../plugins/unit-folder/src/index.ts" lines="418-440" hash="08cda93f2efe" blob="55206a0602ef" */}

**浏览那五条**（`list` / `listDir` / `readFile` / `open` / `code`）里，`list` 回执带 `pinned`——置顶单元条目的数组，
按置顶先后。`list` 每次现扫时顺带清掉过期的状态：置顶了但清单里找不到的（目录删了、换了容器根）从置顶表里摘掉并存盘；
最近一次点击的单元不在清单里的，清掉这次点击。不然一个删掉的单元会一直占着「当前」。两样清完只判一次变没变、最多广播一次：

## 依赖谁

注入了哪些服务、哪些是必需哪些是局部注入、peer 怎么写、缺了会怎样，以及按名字调用的命令与约定通道，见[插件之间怎么连](/docs/wiring)。

**关系是单向的**：别的插件局部注入 `ctx.gwbUnitFolder` 问「人现在看的是哪个单元」或登记工具条按钮，
本插件不认识任何消费方——方向是特殊认识一般，判据见轨迹卡[「选中往外报」](/trajectory/2026-09-09-report-selection-not-extension-point)。
